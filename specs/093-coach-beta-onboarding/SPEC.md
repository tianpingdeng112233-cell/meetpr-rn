## 1. 要解决什么（2026-10-16 现场核实）

教练现在要走完「拿到 App → 有账号 → 学员绑上来」，每一步都要人工答疑：

| 环节 | 现状 | 问题 |
|---|---|---|
| 申请 | 没有入口。教练账号由 David 在后台手开（spec 091「教练账号仍由 David 后台开」） | 教练不知道找谁、要提供什么；David 每个都要手工处理 |
| 注册 | App 内注册角色写死 `coached_student`，教练不能自助注册 | 教练如果自己在 App 里点「注册」，会变成一个学员账号 |
| 装包 | iOS 走 TestFlight；安卓 CN 轨是 APK 直发（微信／网盘）；安卓 Global 轨通道还没定（PARITY「分发通道 ☐」）；网页是 plan-web | 三个平台三种装法，没有一个地方讲清楚；CN 与 Global 是两套后端、两个包，装错了账号和邀请码都对不上 |
| 邀请学员 | 教练在「我的」里复制 10 位邀请码，自己写话发给学员（`coach.roster.noStudentsSubtitle`） | 学员只拿到一串码，不知道去哪下 App、下哪个包、码填在哪 |
| 填码 | 学员注册后在绑定页手输 10 位码 | 如果教练发的是一段话或一个链接，学员整段粘进去，`normalizeInviteCode` 会取前 10 个字母数字，得到错码 |
| 看漏斗 | 只有 `bind_enter_code` / `pending_bind` 两个点 | 不知道人卡在申请、装包、注册还是填码 |

## 2. 设计：两条链接 + 一个按设备分流的落地页

整条链路只给人两条链接，其余都由页面按设备和构建轨替人选好：

- **教练入驻链接**（所有教练同一条）：`<站点>/coach`。David 在任何地方发这一条就够了。
- **学员邀请链接**（每个教练一条，由他的永久邀请码生成）：`<站点>/i/<邀请码>`。教练只需要把这一条发给学员。

两条链接打开的都是同一个落地页框架：识别设备（iPhone／安卓／电脑）与是否在微信里，只显示这台设备该点的那一个按钮。

本期只做 CN 轨（拍板 1），所以站点只有一个，就是 plan-web 现在的地址 `http://121.40.160.241:3000/`（拍板 4；plan-web 由 CN 后端同源托管，新页面靠它已有的单页回退直接可达，链接形如 `http://121.40.160.241:3000/i/<码>`），上面只出现 CN 包的安装按钮，从根上杜绝装成 Global 包。

### 全流程（三个角色）

```
教练                         David                         学员
 │ ① 打开入驻链接，填申请表
 │   （约 1 分钟）
 │ ② 收到「已收到申请」邮件
 │                            ③ 后台申请列表点「通过」
 │                               → 系统建教练账号、生成永久邀请码、
 │                                 发欢迎信（一步完成）
 │ ④ 欢迎信点「设置密码」
 │   → 网页设密码（= 注册完成）
 │ ⑤ 进「入驻完成页」：
 │   · 按设备给装 App 按钮
 │   · 网页排计划入口（plan-web）
 │   · 我的邀请链接 + 二维码 +
 │     「复制邀请消息」
 │ ⑥ 在 App 里用邮箱+密码登录
 │ ⑦ 把邀请消息发给学员 ─────────────────────────────────→ ⑧ 点链接，落地页显示
 │                                                           「××教练邀请你加入 MeetPR」
 │                                                           + 本机该点的装包按钮
 │                                                           + 三步说明
 │                                                         ⑨ 装 App → 注册 → 绑定页
 │                                                           一键粘贴邀请码 → 提交
 │ ⑩ App「接收」队列里点接受（现有功能）←────────────────────┘
```

时间目标：教练 ①→⑦ 不超过 10 分钟、不需要问任何人；学员 ⑧→⑨ 不超过 5 分钟；David 审批一个教练只点一下。

## 3. 网页（建议放进 plan-web 仓，见 §8 拍板 3）

### 3.1 教练申请页 `/coach`

- 字段：姓名、邮箱、手机或微信（选填，方便 David 联系）、大概带多少学员、主要用什么设备（iPhone／安卓／都有）。构建轨不让教练选，由站点决定。
- 提交后显示「已收到，通常 1 个工作日内处理，结果会发到 {邮箱}」，同时发一封同内容的确认信。
- 同一邮箱重复提交：不建第二条，提示「这个邮箱已经提交过申请」。邮箱已经是 MeetPR 账号：照常接收，交给 David 审批时处理（见 §7）。
- 防滥用：按 IP 与邮箱限速；不加图形验证码（内测量小，先不加）。

### 3.2 设密码页（欢迎信里的链接）

- 只有两个框：新密码、确认密码（规则与 App 一致，8–72 位）。链接 7 天有效；过期页面给「重新发送」按钮。
- 设完即登录网页，跳到入驻完成页。教练从此用邮箱 + 密码在 iOS／安卓／网页三处登录。

### 3.3 入驻完成页（教练登录后随时能回来看）

自上而下三块，每块一个主按钮：

1. **装 App**：按访问设备只显示一个按钮（规则同 §3.5 的分流表）；电脑上打开则并列显示 iPhone 与安卓两个二维码。按钮下方一行字：「装好后选『登录』，用 {邮箱} 和刚设的密码。不要点『注册』——注册出来的是学员账号。」
2. **网页排计划**：进 plan-web 的按钮。
3. **邀请学员**：大字显示邀请链接、二维码（可存图）、按钮「复制邀请消息」，复制的是 §6.2 的整段消息，链接已填好。旁边小字：「这条链接可以发给所有学员，长期有效；学员提交后，你在 App『接收』里确认即可。」

### 3.4 学员邀请落地页 `/i/<邀请码>`

- 顶部：「{教练显示名} 邀请你加入 MeetPR」+ 分组显示的邀请码（与 App 一致的 4-3-3 分组）。
- 主按钮「复制邀请码并去安装」：先把邀请码写进剪贴板，再跳到本机对应的安装地址。
- 三步说明：① 安装 App ② 打开后注册账号 ③ 在「输入邀请码」那一页点「粘贴」。
- 码无效（被撤销／过期／用完／不存在）：显示「这个邀请已经失效，请联系你的教练要一个新的」，不显示安装按钮。

### 3.5 按设备分流

| 访问设备 | 显示什么（CN 轨） |
|---|---|
| iPhone | 现有 TestFlight 公开链接（CN 包） |
| 安卓 | 现在发给内测员的 APK 网盘链接（CN 包，`com.meetpr.app`）；换新包时只改这一个链接 |
| 电脑 | 两个二维码 |
| 微信内置浏览器 | 不给下载按钮，改为提示「点右上角 ··· 选『在浏览器打开』」 |

两个安装链接做成 plan-web 的配置项（不写死在页面里），David 发新包时改配置即可。

平台限制（写进落地页的小字或说明）：

- **TestFlight**：要先装 Apple 的 TestFlight App；公开链接最多 10,000 人；每个新版本的第一个外部测试构建要过苹果的 Beta 审核（通常一天内）；构建 90 天后过期，所以必须保证公开链接下始终有一个未过期的构建。iOS 的 CN／Global 是否已是两个 App（两个 Bundle ID）待 iOS 会话核实。
- **安卓 APK**：首次安装要允许「安装未知应用」，页面写一行引导。微信会拦截 APK 下载，所以上表单独处理微信。按拍板 4 继续用网盘链接；网盘页面在手机上可能要多点一两下，落地页说明里写清楚。

## 5. App 改动（iOS 与安卓同步，需要 David 豁免 v1 规则）

改动刻意压到最小，全部集中在两处已有页面：

- **A1 绑定页认得链接**（学员端，`BindGate` 的输入邀请码页）：输入或粘贴的内容里如果有 `/i/<码>`，取出这 10 位码；没有链接时找文中的 10 位码（可带空格或短横分组）；都没有保持现有规则。修掉「整段粘贴得到错码」（原来输入框限长 12，整段粘贴会先被截断）。两轨都生效（纯修错，不改界面）。
- **A2 绑定页「粘贴邀请码」按钮**（学员端，仅 CN 轨）：码框下加一个「粘贴邀请码」文字按钮，点了才读剪贴板，经 A1 取码后填入。不在进页时自动读剪贴板——iOS 每次读都会弹「允许粘贴」，安卓 13+ 会弹提示，自动读体验更差。
- **A3 教练端「复制」改为发邀请**（仅 CN 轨；教练端「我的」邀请码卡与邀请码页）：所有「复制」复制 §6.2 的整段邀请消息（不再只是码）；邀请码页的永久码旁加「分享」，调系统分享面板（「我的」页的卡片位置不够，只保留复制）。文案按手机语言出中英文。链接 = App 连的后端地址 + `/i/<码>`（plan-web 与后端同源）。Global 轨维持只复制码。
- **A3 的发包顺序**：带 A3 的 App 包发出去之前，plan-web 的 `/i/<码>` 落地页必须已上线，否则学员点链接只会看到教练登录页。

暂不做：

- **App Links／Universal Links**（点链接直接拉起已装的 App 并带码）：要在站点挂验证文件、两端都配，收益只在「学员已装 App」的少数情况。放到二期。
- **装完自动带码**（deferred deep link）：不引第三方 SDK 做不到，不做。靠 A2「粘贴」覆盖。
- 教练在 App 内申请或注册：申请与设密码都在网页完成，App 登录页不变。

## 6. 运营物料（不改代码，今天就能先用）

### 6.1 教练欢迎信要点

主题：「欢迎加入 MeetPR 内测」。正文三个按钮，顺序固定：设置密码 → 安装 App → 邀请学员（后两个都指向入驻完成页对应位置）。一句醒目提示：在 App 里选「登录」，不要选「注册」。

### 6.2 邀请消息模板（A3 与入驻完成页复制的就是它）

中文：

> 我在用 MeetPR 给你排训练计划和看动作视频。
> 1. 点这个链接安装 App：{邀请链接}
> 2. 打开 App 注册账号
> 3. 在「输入邀请码」页点「粘贴」，或输入：{分组邀请码}
> 我这边确认后你就能看到训练计划了。—— {教练名}

English:

> I'm using MeetPR to plan your training and review your lift videos.
> 1. Install the app: {invite link}
> 2. Open it and create an account
> 3. On the invite code screen, tap Paste, or enter: {grouped code}
> Once I accept, your plan will show up. — {coach name}

### 6.3 一期之前的过渡做法

后端与网页做好之前，可以先用一张静态的「教练入驻指南」页（每轨一张）+ 一个现成表单服务收申请：页里放各平台安装链接与 6.2 的模板，David 仍在后台手开账号。能解决「不知道去哪装、怎么跟学员说」，不解决「申请与开号要人工」。

## 7. 边界情况

| 情况 | 处理 |
|---|---|
| 教练在 App 里自己点了注册，已有一个学员账号 | 申请照收；David 审批时看到「该邮箱已是学员账号」，二选一：改用别的邮箱，或后台把这个账号转成教练（仅当它没绑过教练、没有训练数据）。不自动转 |
| 学员装错轨的包 | 站点只给本轨按钮，基本避免；若仍发生，App 里邀请码报无效，落地页说明里写「请用这条链接里的按钮安装」 |
| 教练重新生成了永久码 | 旧链接立即失效（现有确认框已提示「已分享出去的也会失效」）；落地页显示失效文案。入驻完成页永远显示当前有效的码 |
| 设密码链接过期 | 页面提供「重新发送」；按邮箱限速 |
| TestFlight 构建过期 | 公开链接仍在但没有可装版本。发版纪律：过期前 2 周补一个构建（iOS 会话跟） |
| 微信打开链接 | 见 §3.5，引导到浏览器 |
| 链接是明文 http + IP，微信里可能被标「非官方网页」或打不开 | 落地页本来就要引导到浏览器打开（§3.5）；彻底解决要等域名 + HTTPS（与 App 切 HTTPS 同一件事，另立） |
| 落地页打开但后端不可达 | 照常显示安装按钮与码（码从链接里取），只是不显示教练名 |

## 9. 怎么算做成了（验收）

1. 新教练只收到入驻链接，不问任何人，10 分钟内完成申请后的设密码、在一台手机上装好并登录 App、发出邀请消息（找 1 位没接触过 MeetPR 的人实测，录屏）。
2. iPhone、安卓、电脑、微信内四种方式打开学员邀请链接，各自只看到该看的按钮；电脑上二维码能被两种手机扫开。
3. 学员从点链接到提交绑定不超过 5 分钟；在绑定页点「粘贴」能填入正确的码（剪贴板里是整段邀请消息也行）。
4. 失效码、过期设密码链接、重复申请、已是学员账号的邮箱，四种情况都按 §7 表现。
5. 站点上只出现 CN 包的安装按钮；iOS 与安卓按钮指向的就是目前内测在用的 TestFlight 与网盘链接。
6. 漏斗：能看到每一步的人数（申请 → 通过 → 设密码 → 首次登录 App → 落地页打开 → 绑定提交 → 教练接受）。
