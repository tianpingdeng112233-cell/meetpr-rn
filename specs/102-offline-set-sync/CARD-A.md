# 102 · 卡 A（安卓 RN）— 打勾先变绿：组记录本机排队、后台同步

先读仓根 `CONTEXT.md`、`AGENTS.md`，再完整读 `specs/102-offline-set-sync/SPEC.md`（含末尾「屏幕稿」节），它是唯一的验收口径，本卡只补执行细节。分支 `feat/102-offline-set-sync`，worktree `meetpr-rn-wt-102`，依赖已装好（npm）。iOS 有一张镜像卡（卡 B）同批在做，两端的行为、时长（20 秒）和文案必须一致。

## 为什么一张卡
同步队列、叠加显示、长按完成前的同步与失败态、退出弹窗都在学员今日训练这一块，拆开验不了「点了就算数」这件事，所以合成一次交付。

## 目标（对应 SPEC 各节）
1. **同步队列**（§1、§6）：新建一个与界面无关的队列模块（建议放 `src/features/training/set-sync/`），用 AsyncStorage **按用户 id 分开存**，杀 app 后能恢复。范围是 SPEC §1.1 列出的全部入口：主项和变式的 `SetEntrySheet.tsx`「完成本组」「未完成 / 失败」（立即关页），辅助项、不定重量和学员自加的卡内行（`AccessoryLogCard.tsx` 等）的打勾、取消、改数、加组、删自加组、「全部按计划完成」。这些操作都改成先入队、立即更新界面，再由队列按顺序发送（`setsRepository.upsert` / `remove`，以及 092 自加写入）。现有的 `serial-task-queue.ts` 可以复用成发送串行器，不要再造第二套串行机制。
2. **失败策略**：网络错误、408、5xx 指数退避重试，网络恢复时立即重试（项目已有网络状态来源就复用，没有就在 JOURNAL 说明用了什么）。不可重试的 4xx 标记为「没传上」并停止自动重试。**不回滚界面**，不弹错误，训练过程中**不显示任何同步提示**。`sets.ts` 的 30 秒超时可以保留，作为单次请求的超时。
3. **叠加显示**（§6）：写一个纯函数「服务器快照 + 队列 → 行状态」，今日训练的数据来源都要经过它。刷新、切 tab、冷启动后已勾的组不能变回没勾。
4. **长按完成**（§2，改的是 `HoldToCompleteButton.tsx` / `CompletionControls.tsx` / `hold-to-complete.ts` 一带）：长按后如果队列里还有这天的记录，立即插队发送，按钮原位显示「正在同步训练记录…」（稿 ①）。同步完成后照常出奖励（`WorkoutCelebrationView`），再调完成接口。队列本来就空则直接出奖励，不要闪同步状态。**20 秒**没同步完，或者遇到 4xx，就进入失败态（稿 ②）：橙色提示块加「重试」按钮，不出奖励，也不调完成接口。点「重试」重新计时；离开页面再回来，按钮恢复为长按。
5. **完成闸门**：写成一个独立模块，输入是「这天的组是否全部同步」，并为 spec 101 预留「视频是否全部送达」输入（101 还没实装，现在恒为真；101 的 RN 卡会叠在你的分支上接这个输入），**不要把闸门写死在组件里**。闸门状态要落盘，杀进程后能恢复。
6. **视频**（§2.7）：`video-upload/manager.ts` 的 `ensureSetLog` 现在会直接调 `setsRepository.upsert`，要改成等这一组在队列里同步完、拿到服务端 id 再挂视频。断网时点组号拍视频必须能拍，视频进现有上传流程等待。
7. **计划动作被删**（§3）：发送时后端表示计划动作不存在（实测返回码写进 JOURNAL），就改按 092 自加动作写入这一天，用原来的 `exercise_id`，数据原样保留。
8. **退出登录**（§5，稿 ③）：学员端退出入口在队列非空时弹窗。「先上传再退出」时立即发送并显示进度，队列清空后执行原来的 `logout`，传不完时可以取消。「直接退出」时队列留在本机。换账号登录时只读当前账号自己的队列。弹窗优先复用仓内现有确认弹窗组件。
9. **文案**：进 `src/i18n` 现有 key 体系（简中、英文手写），繁体跑 `npm run i18n:zh-Hant` 生成，不手写。文案以 SPEC「文案」表为准。

## 约束

- 网络正常时，服务器最终数据必须与改动前同样操作的结果一致。
- 遵守仓内 eslint / tsc 配置。不 commit、不 push、不开 PR、不改锁文件、不改 `PARITY.md`。不新增依赖，确实需要的话先在 JOURNAL 说明理由并停下。

## 测试 seam（先红后绿，红必须实际跑出来）
1. 队列模块单测（主力）：注入发送函数、时钟、网络状态、存储。覆盖：按序发送；失败重试不回滚；同一组多次改以最后一次为准；4xx 标记没传上并停止；「立即发送」插队；按用户隔离；从存储重建。
2. 叠加纯函数单测：勾选、取消勾选、改数、刷新后不回退。
3. 完成流程单测（注入时钟）：队列空时直接奖励；20 秒内同步完时先同步后奖励；超过 20 秒或遇 4xx 进失败态，不奖励、不调完成；重试重新计时；完成接口只调一次；视频条件为假时不调完成。
4. 计划动作不存在时改写自加：在发送层注入错误。
5. 组件级：复用 `src/features/training/__tests__/completion-entry.test.tsx` 的 mock 方式，补两条用例。一是请求挂起时点 ✅，界面立即变绿、其他组可点；二是请求挂起时在 SetEntrySheet 点「完成本组」，页面立即关闭。
6. 全量 `npm test`、`npx tsc --noEmit`、`npm run lint` 全绿。`student-conversation-screen.test.tsx` 在 CI 上偶发失败，本地遇到就写进 JOURNAL，不要修。
