## 给 101 的完成闸门接口

位置：`src/features/training/set-sync/completion.ts`。生产实例由 `accountSetSync(studentId).gate` 唯一持有，不要另建完成接口调用链。

```ts
type CompletionConditions = {
  setsSynchronized: boolean;
  videosDelivered: boolean;
};
declare class CompletionGate {
  constructor(userId: string, storage: SyncStorage,
    complete: (dayId: string) => Promise<unknown>);
  readonly ready: Promise<void>;
  arm(dayId: string): Promise<void>;
  release(dayId: string): Promise<void>;
  updateConditions(dayId: string, conditions: CompletionConditions): Promise<void>;
  pendingDays(): string[];
  forget(dayId: string): Promise<void>;
  dispose(): void;
}
```

`arm` 落盘完成意图，奖励触发后 `release` 才允许发送；两条件同时为真才调完成接口。成功标记落盘，并发唤醒在实例内串行。撤销已完成日用 `forget`；退出账号用 `dispose`。存储键为 `training.completion-gate.v1.${userId}`。

101 接入时须同时替换 `TodayWorkoutView` 协调器的 `videosDelivered` 回调和 `runtime.ts` 恢复流程中目前恒为 `true` 的视频条件；视频送达事件调用同一 gate 的 `updateConditions`。组条件取 `queue.pending(dayId).length === 0`。视频恢复链路通过 `ensureVideoSet(studentId, stableSetId, request?, existingId?): Promise<string>` 等待实际服务端 ID。
